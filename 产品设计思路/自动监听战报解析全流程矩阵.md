# 自动监听战报解析全流程矩阵

更新时间：2026-07-15

## 说明

本文只说明“自动监听战报解析”的核心全流程。

重点回答四个问题：

- 每一步由谁触发？
- 图片文件存在哪里？
- 图片和结果怎么流转？
- 关键业务信息怎么从前一步传到后一步？

不展开代码实现、接口细节、数据库结构、页面细节和后续优化方案。

## 全流程矩阵

| 序号 | 流程阶段 | 触发方 | 当前动作 | 文件存储位置 | 文件流转 | 关键信息流转 | 输出结果 | 用户可见状态 |
|---:|---|---|---|---|---|---|---|---|
| 1 | 安装本地助手 | 用户 + 安装程序 | 用户安装本地助手；安装完成后本地助手自动启动，不需要用户再点桌面图标 | 本地电脑 | 暂无图片流转 | 生成或读取本机设备信息 | 本地助手自动运行 | 助手未授权 / 等待授权 |
| 2 | 授权本地助手 | 用户 + 网页 + 本地助手 | 安装后自动打开授权网页；也支持用户从托盘右键打开助手界面，再点击授权打开网页 | 本地助手保存授权凭证 | 暂无图片流转 | 账号信息、设备信息、助手授权信息建立关联 | 助手知道自己属于哪个账号 | 助手已授权 |
| 3 | 确认项目上下文 | 用户 + 网页 | 用户进入某个项目，或在项目内下载/打开本地助手 | 暂无文件变化 | 暂无图片流转 | 当前账号、当前项目传入监听配置；如果用户下载前已经在项目中，则默认带入当前项目 | 明确“帮哪个项目监听” | 当前项目已选定 |
| 4 | 选择监听目录 | 用户 + 网页 + 本地助手 | 用户选择截图保存目录 | 用户本地文件夹 | 原始截图仍留在本地目录 | 当前项目、监听目录、绑定助手形成监听配置 | 监听任务具备目录来源 | 已选择监听目录 |
| 5 | 开始监听 | 用户 + 网页 | 用户点击开始监听 | 原始截图仍留在本地目录 | 不移动、不删除本地图片 | 监听状态从未运行变为运行中 | 本地助手开始按配置工作 | 监听中 |
| 6 | 扫描本地目录 | 本地助手 | 助手定时读取目录里的全部图片名称列表 | 用户本地文件夹 | 只读取文件名称，不改动图片 | 图片名称列表 | 得到当前目录全量图片名称 | 助手在线、最近扫描时间更新 |
| 7 | 判断是否新图片 | 本地助手 + 服务端 | 用本地全量图片名称列表，对比已提交、处理中、已成功的图片名称列表 | 本地文件夹 + 系统记录 | 图片仍在本地目录 | 当前项目、图片名称、处理状态 | 得到新增图片名称差异列表 | 待处理数量可能变化 |
| 8 | 提交图片到待处理区 | 本地助手 | 助手只提交差异列表里的新增图片 | 本地目录保留原图；系统待处理区保存一份图片 | 图片从本地复制到 MySQL 中的独立过程区 | 账号、项目、助手、图片名称、图片内容 | 生成一条待解析任务 | 待处理 +1 |
| 9 | 排队等待解析 | 系统 | 系统按顺序维护待解析任务 | MySQL 独立过程区 | 图片暂存在过程区 | 任务状态、提交时间、来源项目、来源助手 | 等待 OCR 处理 | 图片显示为等待中 |
| 10 | 开始 OCR 解析 | 系统 | 系统取出一张待处理图片开始识别 | MySQL 独立过程区 + OCR 临时缓存 | 从过程区读取图片，放入 OCR 当前处理缓存，送入 OCR 识别 | 图片内容、项目识别配置、武将/战法/玩家等识别辅助信息 | 任务进入解析中 | 图片显示为解析中 |
| 11 | OCR 产出原始识别结果 | OCR 服务 | OCR 返回识别文本和位置结果 | 临时处理内存 | 图片不产生新副本 | 原始识别文本、识别位置、置信度等信息 | 得到原始 OCR 结果 | 用户通常不直接看到 |
| 12 | 转换为战报结构 | 系统 | 系统把 OCR 原始结果整理成战报字段 | 临时处理内存 | 图片仍在过程区，OCR 缓存只服务当前图片 | 玩家、同盟、阵型、胜负、武将、红度、战法、战损、兵力等信息 | 得到结构化战报结果 | 仍显示解析中 |
| 13 | 校验解析结果 | 系统 | 检查结果是否足够形成一条有效战报 | 临时处理内存 | 图片仍在待处理区 | 必填信息、识别完整度、异常信息 | 判断成功或失败 | 成功继续，失败进入失败状态 |
| 14 | 保存正式战报 | 系统 | 将结构化结果保存为正式战报 | 正式战报库 | 图片本身不进入战报文字结果 | 项目、玩家、武将、战法、胜负、战损、时间等正式战报信息 | 新增一条正式战报 | 战报列表可刷新出新记录 |
| 15 | 保存战报原图 | 系统 | 将原始图片保存到战报图片库 | 战报图片库 | 图片从 MySQL 过程区复制到正式图片库 | 图片名称、图片内容、所属项目、所属战报 | 原图与正式战报建立关联 | 可查看原图 |
| 16 | 扣减解析额度 | 系统 | 成功解析后扣减用户额度 | 不涉及文件 | 无文件流转 | 账号、扣减数量、解析说明 | 额度更新，形成消费记录 | 用户额度减少 |
| 17 | 完成任务 | 系统 | 标记该图片处理完成 | 正式战报库 + 战报图片库保留；过程区准备释放 | 图片正式副本已保存，过程副本进入清理环节 | 任务状态、完成时间、关联战报 | 任务从处理中变为已完成 | 待处理 -1，已完成 +1 |
| 18 | 删除过程图片 | 系统 | 删除已成功任务在 MySQL 过程区里的图片内容 | MySQL 过程区 | 删除过程图片大字段，只保留必要任务摘要 | 任务编号、图片名称、完成时间、关联战报、清理状态 | 释放过程存储空间 | 用户无感知 |
| 19 | 释放 OCR 当前缓存 | 系统 + OCR 服务 | 清理当前图片解析时占用的临时内存和缓存 | OCR 临时缓存 | 当前图片处理缓存释放，不积压到下一张 | 当前任务结束信号、缓存释放结果 | OCR 准备处理下一张图片 | 用户无感知 |
| 20 | 刷新页面数据 | 网页 | 页面重新拉取最新结果 | 不涉及文件 | 无文件流转 | 最新战报、任务状态、统计数量 | 页面展示最新战报和统计 | 战报列表、待处理数、完成数更新 |
| 21 | 解析失败 | 系统 | OCR 或结果校验失败 | 图片保留在 MySQL 过程区 | 不写入正式战报，不写入正式图片库；释放 OCR 当前缓存 | 失败原因、失败时间、可重试状态 | 任务变为失败 | 失败 +1，可重试 |
| 22 | 重试失败任务 | 用户 + 系统 | 用户点击重试，系统重新解析 | 继续使用 MySQL 过程区里的图片 | 不需要重新从本地上传图片 | 原任务信息、图片内容、重试次数 | 失败任务重新进入等待解析 | 失败任务回到等待中 |
| 23 | 清理无效过程数据 | 系统或用户 | 清理不再需要的失败、取消或过期任务 | 正式战报和正式图片保留 | 只清理过程区副本或过程记录 | 保留正式结果，释放过程占用 | 系统更轻量 | 历史战报不受影响 |

## 文件存储流转说明

| 阶段 | 文件位置 | 是否是正式存储 | 是否建议保留 | 说明 |
|---|---|---|---|---|
| 原始截图 | 用户本地监听目录 | 否 | 由用户决定 | 系统只读取，不主动删除或移动 |
| 待处理图片 | MySQL 独立过程区 | 否 | 临时保留 | 用于排队、OCR、失败重试和排查 |
| 正式原图 | 战报图片库 | 是 | 长期保留 | 解析成功后用于回看原图 |
| 正式战报 | 正式战报库 | 是 | 长期保留 | 保存结构化战报结果 |
| OCR 当前缓存 | OCR 服务临时内存 | 否 | 单图处理后立即释放 | 只服务当前图片，不能积压 |
| 过程副本 | MySQL 独立过程区 | 否 | 成功后删除图片内容 | 成功任务不应长期占用大量空间 |

## 关键信息流转说明

| 信息类别 | 来源 | 流转过程 | 最终用途 |
|---|---|---|---|
| 账号信息 | 用户登录和助手授权 | 授权助手 → 选择项目 → 提交图片 → 成功扣减额度 | 判断归属、权限和额度 |
| 助手信息 | 本地助手 | 授权 → 绑定项目监听 → 扫描目录 → 提交图片 | 确认是哪台电脑在监听 |
| 项目信息 | 网页当前项目 | 选择项目 → 监听配置 → 图片入队 → 正式战报 | 确认战报属于哪个项目 |
| 目录信息 | 用户选择的本地文件夹 | 保存到监听配置 → 本地助手扫描 | 确认图片从哪里来 |
| 图片信息 | 本地截图文件 | 扫描图片名称 → 名称差异对比 → 提交新增图片 → MySQL 过程区 → OCR → 正式原图 → 删除过程图片 | 支撑识别、去重和回看 |
| 识别配置 | 项目配置和识别字典 | OCR 前加载 → OCR 识别 → 结果转换 | 提升识别准确率 |
| 战报信息 | OCR 结果转换 | 原始识别 → 结构化结果 → 正式战报 | 用于战报查询、分析和展示 |
| 状态信息 | 系统维护 | 等待中 → 解析中 → 已完成 / 失败 | 页面展示进度和异常 |
| 额度信息 | 用户账户 | 解析成功后扣减 | 控制 OCR 使用成本 |

## 核心边界

| 边界 | 说明 |
|---|---|
| 本地助手只负责发现和提交图片 | 不负责判断最终解析是否成功，也不直接生成正式战报 |
| 系统待处理区就是 MySQL 独立过程区 | 待解析图片直接保存在 MySQL 的过程区，不另设服务器文件夹作为主存储 |
| 正式战报和正式图片分开保存 | 战报是结构化结果，图片是原始证据 |
| 失败任务不直接丢弃 | 保留图片和失败原因，方便用户重试或排查 |
| 成功任务必须释放过程图片 | 正式原图保存后，删除 MySQL 过程区里的图片内容，避免过程区越来越臃肿 |
| OCR 当前缓存必须单图释放 | 每张图片解析结束后释放临时缓存，再处理下一张 |

## 补充规则

### 项目上下文

如果用户是在某个项目中下载本地助手，或者在项目页面里完成授权，系统应默认带入当前项目。

也就是说：

| 场景 | 默认项目处理 |
|---|---|
| 用户已经在项目内下载助手 | 当前项目自动作为默认监听项目 |
| 用户已经在项目内授权助手 | 当前项目自动作为默认监听项目 |
| 用户从非项目页面安装或授权 | 后续进入项目时再选择项目 |
| 用户切换到其他项目 | 需要重新确认该项目的监听目录和监听状态 |

项目上下文只负责减少用户操作，不代表本地助手自己决定监听哪个项目。最终仍以网页当前项目和用户确认的监听配置为准。

### 扫描和差异判断

扫描采用“本地全量名称扫描 + 名称差异提交”的方式。

前提规则：

> 每张截图的图片名称都是唯一的，所以判断是否新图片只看图片名称，不再比较文件大小、修改时间，也不计算图片指纹。

| 步骤 | 判断方式 | 说明 |
|---|---|---|
| 1 | 全量读取本地目录图片名称 | 每轮只读取目录里的图片名称列表 |
| 2 | 获取系统已记录图片名称 | 包括已提交、等待中、解析中、已成功的图片名称 |
| 3 | 做名称差异对比 | 本地名称列表 - 系统已记录名称列表 = 新增图片名称列表 |
| 4 | 只提交新增图片 | 只把差异列表里的图片提交到待处理区 |
| 5 | 更新监听展示 | 待处理数量和列表按新增结果刷新 |

这样用户理解上是“监听整个目录”，系统执行上是“每轮读取全量名称，只提交新增差异图片”。

### 本地助手启动和授权入口

安装和授权需要尽量少打扰用户：

| 场景 | 处理方式 |
|---|---|
| 首次安装完成 | 安装程序自动启动本地助手 |
| 助手首次启动且未授权 | 自动打开授权网页 |
| 用户关闭授权网页 | 助手保持未授权状态，托盘里仍可重新发起授权 |
| 用户右键托盘图标 | 打开本地助手界面 |
| 用户在助手界面点击授权 | 弹出授权网页，用户登录后点击授权 |
| 授权完成 | 本地助手保存授权信息，界面显示已授权 |

默认主路径是“安装完成 → 自动启动助手 → 自动打开授权网页”。托盘右键入口是补充路径，用于用户后续重新授权或授权失败后重试。

### 完成后的释放动作

解析成功后需要做两个释放动作：

| 释放对象 | 释放时机 | 处理方式 |
|---|---|---|
| MySQL 过程区图片 | 正式战报和正式原图都保存成功后 | 删除过程区里的图片内容，只保留必要摘要 |
| OCR 当前缓存 | 当前图片 OCR 成功或失败后 | 清理临时图片、临时识别结果和内存占用 |

文档前面写的“待处理副本可清理”，指的就是第一项：成功后删除 MySQL 过程区里的图片内容。
