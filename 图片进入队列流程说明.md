# 待处理图片如何进入数据库队列

## 核心概念

**ocr_pending_tasks 表** 就是队列本身！
- 它不是"进入队列"，而是**插入一条数据库记录**
- 每条记录就是一个待处理任务
- 队列处理器通过 SQL 查询轮询这张表

## 完整流程

```
┌──────────────────────────────────────────────────────────┐
│  图片来源                                                  │
├──────────────────────────────────────────────────────────┤
│  1. 本地助手扫描文件夹（自动监听模式）                      │
│  2. 网页手动上传图片                                       │
└──────────────────────────────────────────────────────────┘
                         ↓
┌──────────────────────────────────────────────────────────┐
│  后端API接收图片                                           │
├──────────────────────────────────────────────────────────┤
│  POST /api/battles/ocr-tasks                              │
│  - 接收 Base64 图片数据                                    │
│  - 验证用户积分（不预扣）                                   │
│  - 检查图片是否已存在                                       │
└──────────────────────────────────────────────────────────┘
                         ↓
┌──────────────────────────────────────────────────────────┐
│  INSERT 到数据库                                           │
├──────────────────────────────────────────────────────────┤
│  INSERT INTO ocr_pending_tasks                            │
│  (user_id, project_id, image_base64, image_name,          │
│   helper_task_id, status, created_at, updated_at)         │
│  VALUES (?, ?, ?, ?, ?, 'pending', NOW(), NOW())          │
│                                                            │
│  ✅ 此时图片已经在"队列"中了！                              │
└──────────────────────────────────────────────────────────┘
                         ↓
┌──────────────────────────────────────────────────────────┐
│  队列处理器自动检测（每秒轮询）                              │
├──────────────────────────────────────────────────────────┤
│  SELECT ... FROM ocr_pending_tasks                        │
│  WHERE status = 'pending'                                 │
│  ORDER BY ... LIMIT 2                                     │
│                                                            │
│  发现新记录 → 自动处理                                      │
└──────────────────────────────────────────────────────────┘
```

## 详细步骤拆解

### 步骤1：图片上传到后端

**自动监听模式（本地助手）**：
```javascript
// local-helper/local-helper.js
async uploadFile(file) {
  const base64 = fs.readFileSync(file, 'base64');
  
  await axios.post('http://localhost:3000/api/battles/ocr-tasks', {
    image: base64,
    projectId: this.config.projectId,
    imageName: path.basename(file),
    helperTaskId: this.taskId  // 关联到自动监听任务
  });
}
```

**手动上传模式（网页）**：
```javascript
// 前端代码
const formData = new FormData();
formData.append('image', fileBase64);
formData.append('projectId', projectId);

axios.post('/api/battles/ocr-tasks', formData);
```

### 步骤2：API处理请求

**位置**：`nslg-backend.js` 第1253-1317行

```javascript
app.post('/api/battles/ocr-tasks', requireOcrUploadActor, async (req, res) => {
  try {
    const { image, projectId, imageName, helperTaskId } = req.body;
    
    // 1. 验证用户
    const [uRows] = await pool.query(
      'SELECT id, credit_balance FROM users WHERE phone = ? LIMIT 1',
      [phone]
    );
    const userId = uRows[0].id;
    
    // 2. 清理Base64格式
    const cleanImage = image.replace(/^data:[^;]+;base64,/, '');
    
    // 3. 检查是否已存在（去重）
    const [existingTasks] = await pool.query(
      `SELECT id, status FROM ocr_pending_tasks
       WHERE user_id = ? AND image_name = ?`,
      [userId, imageName]
    );
    
    if (existingTasks.length) {
      return res.json({
        code: 200,
        message: '图片已在待处理区',
        data: { taskId: existingTasks[0].id, duplicate: true }
      });
    }
    
    // 4. 插入到队列表（核心步骤！）
    const [result] = await pool.query(
      `INSERT INTO ocr_pending_tasks
       (user_id, project_id, image_base64, image_name, 
        helper_task_id, status, created_at, updated_at)
       VALUES (?, ?, ?, ?, ?, 'pending', NOW(), NOW())`,
      [userId, projectId || null, cleanImage, imageName, helperTaskId || null]
    );
    
    // 5. 返回任务ID
    res.json({ 
      code: 200, 
      message: '任务已加入队列', 
      data: { taskId: result.insertId } 
    });
  } catch (err) {
    console.error('[OCR-Tasks] 创建任务失败:', err);
    res.json({ code: 500, message: err.message });
  }
});
```

### 步骤3：队列处理器自动检测

**位置**：`nslg-backend.js` 第1679-1770行

```javascript
async function processOcrQueue() {
  // 持续轮询
  while (isProcessingQueue) {
    // 查询待处理任务（最多取2条）
    const [tasks] = await pool.query(
      `SELECT id, user_id, project_id, image_base64, image_name,
              helper_task_id, label_config
       FROM ocr_pending_tasks
       WHERE status = 'pending'
       ORDER BY
         CASE WHEN helper_task_id IS NOT NULL THEN 0 ELSE 1 END,
         created_at ASC
       LIMIT ?`,
      [availableSlots]  // 2个槽位
    );
    
    if (!tasks.length) {
      // 没有任务，等待5秒后继续检查
      await new Promise(r => setTimeout(r, 5000));
      continue;
    }
    
    // 并发处理任务
    for (const task of tasks) {
      (async () => {
        // 标记为处理中
        await pool.query(
          'UPDATE ocr_pending_tasks SET status = ?, updated_at = NOW() WHERE id = ?',
          ['processing', task.id]
        );
        
        // 执行OCR识别
        await processOcrTask(task);
        
        // 处理完成后，状态会更新为 'completed' 或 'failed'
      })();
    }
    
    await new Promise(r => setTimeout(r, 1000));
  }
}
```

## 关键点总结

### 1. 队列 = 数据库表
- **ocr_pending_tasks 表本身就是队列**
- 不存在"进入队列"的独立动作
- INSERT 一条记录 = 添加到队列

### 2. 状态流转
```
pending → processing → completed/failed
   ↑          ↑             ↑
  插入时    处理器取走      处理完成
```

### 3. 队列处理器轮询机制
```javascript
每1秒检查一次数据库：
  - 查询 status='pending' 的记录
  - 最多取2条（并发限制）
  - 标记为 'processing'
  - 异步执行OCR
  - 更新状态为 'completed' 或 'failed'
```

### 4. 去重机制
在插入前检查：
- 同用户 + 同图片名 → 已在队列中
- 同用户 + 同图片名 + 已成功 → 已解析成功

### 5. 优先级
```sql
ORDER BY
  CASE WHEN helper_task_id IS NOT NULL THEN 0 ELSE 1 END,
  created_at ASC
```
- helper_task_id 不为空（自动监听）优先级高
- 同优先级按创建时间排序

## 对比其他API

### /api/battles/ocr-upload（旧接口，即时处理）
- 收到图片 → 立即调用OCR → 立即保存结果
- **不使用队列**
- 响应慢，容易超时

### /api/battles/ocr-tasks（新接口，队列处理）
- 收到图片 → 插入队列 → 立即返回任务ID
- 队列处理器后台异步处理
- 响应快，不阻塞

### /api/battles/ocr-execute（手动触发）
- 从队列中取出某个 pending 任务
- 手动触发执行
- 用于网页端"立即解析"按钮

## 监控队列状态

```bash
# 查询当前队列
SELECT status, COUNT(*) 
FROM ocr_pending_tasks 
GROUP BY status;

# 结果示例：
# pending: 10    ← 等待处理
# processing: 2  ← 正在处理
# completed: 50  ← 已完成
# failed: 3      ← 失败
```

## 架构优势

### 异步解耦
- 上传和处理分离
- 前端不用等待OCR完成
- 后端可以批量优化处理

### 可靠性
- 处理失败不影响数据
- 可以重试失败任务
- 防止并发冲突

### 可扩展性
- 可以添加多个队列处理器
- 可以设置优先级
- 可以限流控制

### 可观测性
- 所有任务都有记录
- 状态清晰可查
- 便于调试和监控
