### 2. 修改 uploadFile 函数

**位置：** `local-helper.js` 第402行

**修改前：**
```javascript
async function uploadFile(config, task, filePath, fileName) {
  // 每次都获取 labelConfig
  let labelConfig = null;
  try {

  } catch (e) { ... }
  ...

```

**修改后：**

```javascript
  // 如果没有传入labelConfig，则获取（向后兼容）
  if (!labelConfig) {
    try {
      labelConfig = await fetch('/label-config/${projectId}');
    } catch (e) { ... }
  }
  ...
}
```

**说明：** 
- 支持传入缓存的 labelConfig
- 如果不传，仍然会获取（向后兼容）

### 3. 修改 processTask 函数（核心优化）

**位置：** `local-helper.js` 第526-610行

#### 优化1：缓存标注配置

**修改前：**
```javascript
// 逐个上传
for (let i = 0; i < newFiles.length; i++) {
  await uploadFile(config, task, fullPath, fileName);  // 内部每次获取配置
}
```

**修改后：**
```javascript
// 在上传前获取一次配置
let labelConfig = null;
try {
  const configResp = await fetch('/label-config/${projectId}');
  if (configResp.ok) {
    labelConfig = configData.data.categories;
  }
} catch (e) {
  console.warn('获取失败，使用自动检测模式');
}

// 所有文件复用这个配置
```

**效果：**
- 100张图片：从获取100次 → 获取1次
- 节省时间：99 × 300ms = 约30秒

---

#### 优化2：并行上传

**修改前：**
```javascript
// 串行上传（一次一张）
for (let i = 0; i < newFiles.length; i++) {
  await uploadFile(...);  // 等待完成
}
```

**修改后：**
```javascript
// 并行上传（每批5张）
for (let i = 0; i < newFiles.length; i += CONCURRENT_UPLOAD) {
  const batch = newFiles.slice(i, i + CONCURRENT_UPLOAD);
  
  const uploadPromises = batch.map(async (fileName) => {
    return await uploadFile(config, task, fullPath, fileName, labelConfig);
  });
  
  await Promise.all(uploadPromises);  // 并行等待
}
```

**效果：**
- 同时上传5个文件
- 速度提升：约5倍

## 性能对比

### 场景：上传100张战报截图（每张约500KB）

| 指标 | 优化前 | 优化后 | 提升 |
|------|--------|--------|------|
| **单张耗时** | 2秒 | 2秒 | - |
| **labelConfig请求** | 100次 | 1次 | 99倍 |
| **HTTP上传请求** | 串行100次 | 并行20批 | 5倍 |

**计算说明：**
- 优化前：100张 × 2秒 = 200秒
- 优化后：
  - labelConfig获取：1次 × 0.3秒 = 0.3秒
  - 上传：(100张 ÷ 5并发) × 2秒 = 40秒
  - 减去节省的labelConfig时间：40秒 - 30秒 = 10秒
  - 加上任务状态检查：20批 × 0.5秒 = 10秒
  - **总计：约33秒**

## 技术细节

### 并发控制

**为什么是5个并发？**
- ✅ 足够快（5倍提升）
- ✅ 不会过载服务器
- ✅ 错误容易追踪
- ✅ 网络带宽充足

**可调整：**
```javascript
const CONCURRENT_UPLOAD = 5;  // 改为3、10等
```

---

### 错误处理

**每个文件独立处理：**
```javascript
const uploadPromises = batch.map(async (fileName) => {
  try {
    await uploadFile(...);
    return { fileName, success: true };
  } catch (e) {
    return { fileName, success: false, error: e.message };
  }
});
```

**特点：**
- ✅ 单个文件失败不影响其他文件
- ✅ 记录每个文件的结果
- ✅ 继续处理下一批

---

### 任务状态检查

**每批检查一次：**
```javascript
for (let i = 0; i < newFiles.length; i += CONCURRENT_UPLOAD) {
  // 检查任务是否被暂停/删除
  const currentTask = await checkTaskStatus();
  if (!currentTask || currentTask.status !== 'running') {
    return;  // 停止上传
  }
  
  // 上传当前批次
  await Promise.all(uploadPromises);
}
```

**效果：**
- 原来：每个文件都检查（100次）
- 现在：每批检查一次（20次）
- 响应速度：仍然很快（最多5个文件的延迟）

## 风险评估

### 风险1：服务器压力增加

**影响：** 同时处理5个请求，服务器压力增加

**缓解：**
- 5个并发是保守值
- 可根据服务器性能调整
- 如有问题，降低为3

---

### 风险2：数据库连接池

**影响：** 同时插入5条记录，可能占用连接

**缓解：**
- 后端使用连接池
- 5个并发在合理范围
- 监控数据库连接数

---

### 风险3：OCR队列压力

**影响：** 快速上传可能导致OCR队列积压

**缓解：**
- OCR队列有限流机制
- 上传和处理是解耦的
- 不影响上传速度
